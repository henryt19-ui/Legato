# Contributing (proposed team process)

This is an **internal Team 3** project starter. Follow the team's actual collaboration and class/project policies if they differ from this proposed workflow.

1. Work in a topic branch (`docs/...`, `feature/...`, `fix/...`) and open a pull request to `main`.
2. Link the relevant requirement ID (MIH-001 through MIH-010) and design section to the issue and PR.
3. Keep proposed decisions in `docs/open-questions.md` until approved; do not silently change documented requirements.
4. Attach a screenshot or tested prototype reference for UI changes once Figma screens have been confirmed.
5. Keep feature flags and configuration samples free of real secrets.
6. Review role-based permissions, tests, relevant error states, and docs before merging.
7. Treat design material as confidential and avoid public sharing without approval.

At present, no executable code exists; the workflow only checks repository documentation structure and whitespace.
